# Entity-Conditioned Text Processing Rules

Proxy Configuration extends its existing ordered rule list with Text Insertion Rules and optional Entity State Conditions on both insertions and literal/regex Replacement Rules. Insertion modes accept arbitrary literal text at message, line, or sentence starts, allowing text processing to respond to any configured Home Assistant entity state. Explicit insertion modes are needed because existing regex rules run on protected-tag-separated and streamed text segments, where start anchors do not reliably represent the start of the complete TTS message.

Entity State Conditions are evaluated once when response text first becomes available: on the first nonempty input chunk for streaming, or before processing a complete response. The resulting Condition Snapshot applies throughout the message. This keeps delivery consistent if an entity changes state while text is streaming; the proxy does not infer the state of an earlier speech-recognition or conversation stage.

**Timing correction, implemented 2026-10-06:** Assist prepares a TTS stream before speech recognition. The original interpretation of request start as stream preparation caused responses to use the preceding interaction's sensor state. Capturing conditions on response text supersedes that interpretation. An actual HA-manager regression test reproduces the original one-interaction delay and verifies the correction for streamed and complete responses.

**Optional age limit, implemented 2026-10-06:** Each Entity State Condition may set a positive whole-number maximum report age in seconds; omitting it preserves unbounded state matching. Freshness uses HA's `last_reported`, which advances on identical state reports as well as changes ([HA state-report timestamp](https://developers.home-assistant.io/blog/2024/03/20/state_reported_timestamp/)). Age is checked once in the Condition Snapshot and does not expire rules during a response. Users sharing a proxy across speakers create a separate rule for each speaker's entity, accepting this freshness heuristic instead of requiring source-aware routing or newest-entity selection. Multiple entities within one rule are outside this scope.

For integrations that suppress unchanged reports, freshness cannot identify repeated activity with the same value. Users can compose an external HA template helper combining an activity entity with the condition entity and use that helper as the rule's single condition entity without an age limit. This keeps application-specific composition outside TTS Proxy and preserves one entity per rule. Such helpers do not supply the proxy with a request's source identity.

Although both rule types share one configuration list, processing has two phases: Replacement Rules retain their existing position before Markdown Cleanup, while Text Insertion Rules run after Markdown Cleanup and before Text Line Break Cleanup. Each phase follows the configured list order independently. This preserves Markdown heading and list recognition and keeps line starts available for insertions; a Replacement Rule does not process text added by a Text Insertion Rule, regardless of their relative positions in the configuration list.

**Consequences**

Cached audio must respect the Condition Snapshot. Home Assistant's one-shot TTS path checks its cache using original message, language, options, and engine before calling the Proxy TTS Entity ([Home Assistant TTS manager](https://github.com/home-assistant/core/blob/2026.9.4/homeassistant/components/tts/__init__.py#L938-L995)). Conditions cannot safely be read during preparation, so enabled conditioned rules use a unique private request marker to prevent reuse of earlier HA audio. A separate stable configuration fingerprint preserves cache reuse for proxies without enabled conditioned rules and invalidates audio when their processing configuration changes. Both private options are stripped before target delegation.

The marker prevents reuse between requests, not storage. Identical conditioned responses require fresh synthesis, and complete responses with HA file caching enabled can accumulate distinct persistent cache files until the HA cache is cleared. This existing storage behavior is accepted for the first fix; a proxy-owned cache and file-cleanup policy are deferred. Actual Home Assistant 2026.9.4 manager tests validate streaming, one-shot memory and disk cache isolation, stable caching without enabled conditions, and concurrent requests.
